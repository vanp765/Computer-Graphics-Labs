# Отчет по лабораторной работе №3: Базовые растровые алгоритмы

https://vanp765.github.io/Computer-Graphics-Labs/Lab3/

**Цель работы:** Практическое освоение и программная реализация базовых алгоритмов растеризации отрезков и кривых на дискретной сетке.

**Задачи:**
1. Разработать приложение, иллюстрирующее работу 4 базовых алгоритмов (Пошаговый, ЦДА, Брезенхем для прямой, Брезенхем для окружности).
2. Реализовать визуализацию системы координат (оси, сетка, подписи, идеальная математическая линия).
3. Проиллюстрировать алгоритм Брезенхема ручным расчетом.
4. Выполнить замер и анализ временных характеристик алгоритмов.

## Теоретическая база
- **Привязка к сетке:** В разработанном приложении целочисленная математическая координата соответствует геометрическому центру закрашиваемого дискретного пикселя.
- **Пошаговый алгоритм:** Основан на уравнении прямой $y = kx+b$. Выполняет ресурсоемкие операции умножения вещественных чисел и их округления на каждом шаге.
- **Алгоритм ЦДА (DDA):** Заменяет умножение на прибавление малых приращений (`dx/L`, `dy/L`). Работает быстрее пошагового, но всё еще требует программного округления дробей на каждой итерации.
- **Алгоритм Брезенхема (Отрезок):** Идеальный целочисленный алгоритм. В работе реализована **универсальная обобщенная модификация**, не требующая смены «ведущей оси» для разных октантов. Ошибка накапливается в единой переменной `err`, а условия `e2 > -dy` и `e2 < dx` (где `e2 = 2 * err`) проверяют необходимость шага по осям, математически заменяя проверку на отклонение в 0.5 пикселя.
- **Алгоритм Брезенхема (Окружность):** Вычисляет координаты для одного октанта (1/8 окружности) с помощью целочисленного накопителя ошибки. Остальные точки достраиваются симметрично по осям и диагоналям.

## Ручной расчет (Брезенхем, отрезок от 0,0 до 3,2)
Начальные данные: $dx = 3$, $dy = 2$. Ошибка $err = dx - dy = 1$. Удвоенная ошибка $e2$.
- **Шаг 1:** Пиксель **(0,0)**. $e2 = 2$.
  - $e2 > -dy$ (2 > -2) → Шаг по X ($x=1$), $err = 1 - 2 = -1$.
  - $e2 < dx$ (2 < 3) → Шаг по Y ($y=1$), $err = -1 + 3 = 2$.
- **Шаг 2:** Пиксель **(1,1)**. $e2 = 4$.
  - $e2 > -dy$ (4 > -2) → Шаг по X ($x=2$), $err = 2 - 2 = 0$.
  - $e2 < dx$ (4 < 3) → ЛОЖЬ. Y остается 1.
- **Шаг 3:** Пиксель **(2,1)**. $e2 = 0$.
  - $e2 > -dy$ (0 > -2) → Шаг по X ($x=3$), $err = 0 - 2 = -2$.
  - $e2 < dx$ (0 < 3) → Шаг по Y ($y=2$), $err = -2 + 3 = 1$.
- **Шаг 4:** Пиксель **(3,2)**. Достигнута конечная точка.

## Анализ временных характеристик
Был проведен бенчмарк алгоритмов (10 000 итераций). 
Выявлено, что на современных архитектурах (FPU) сложение дробей в ЦДА выполняется за 1 такт процессора. Однако при честном замере, когда алгоритм обязан вычислить итоговую координату пикселя, методы ЦДА и Пошаговый значительно теряют производительность из-за необходимости вызова функции округления. Алгоритм Брезенхема избавлен от вещественной математики и операций округления, благодаря чему демонстрирует наивысшую скорость работы.
